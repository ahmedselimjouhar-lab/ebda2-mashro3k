# ابدأ مشروعك — V5

نسخة عربية موجهة للسوق المصري لاكتشاف الهوية المهنية ونموذج العمل والفرص التي يمكن اختبارها بموارد المستخدم الحالية.

## المكونات

- `index.html`: واجهة الاختبار باللغة العربية المصرية المبسطة.
- `app.js`: إدارة خطوات الواجهة، حفظ الإجابات محليًا، وطلب صفحات الأسئلة والنتيجة من الخادم.
- `styles.css`: التنسيق.
- `about.html`: شرح المنهجية والمراجع وحدود الأداة.
- `api/assessment.js`: بنك الأسئلة، المراجع، مفاتيح الإجابة، المهن، أفكار المشروعات، الأوزان، ومحرك التصحيح. لا يُرسل هذا الملف إلى المتصفح.

تظهر أسفل كل سؤال إشارة مرجعية صغيرة قابلة للفتح. يظهر اسم النموذج أو الدراسة أولًا، ثم التفاصيل الببليوغرافية والجهة والأداة والرابط، مع زر ينسخ المرجع كاملًا. الأسئلة العربية أصلية للموقع؛ ذكر المرجع يوضح مصدر الإلهام ولا يعني اعتماد السؤال من الجهة المذكورة. كما تم توزيع أسئلة الاهتمامات بالتبادل حتى لا تظهر أسئلة البعد نفسه متجاورة بصورة تكشف نمط القياس.

## هل تحتاج النسخة إلى LLM؟

لا. التصحيح وترتيب المهن ونماذج العمل وأفكار التجارب يعملون بقواعد حتمية قابلة للاختبار والتفسير. لا يوجد مفتاح API لنموذج لغوي ولا اعتماد على LLM في النتيجة. يمكن إضافة طبقة اختيارية لاحقًا لصياغة شرح لغوي للنتيجة فقط، مع إبقاء القياس والدرجات خارج النموذج.

## متطلبات النشر على Vercel

1. اجعل مستودع GitHub **Private** قبل وضع كود الخادم فيه.
2. ارفع محتويات الحزمة في جذر المستودع، مع الحفاظ على مجلد `api` كما هو.
3. في Vercel، اجعل Root Directory هو جذر المستودع، وFramework Preset هو `Other`. لا يوجد Build Command مطلوب لهذه النسخة.
4. أنشئ قيمة سرية بطول 32 حرفًا أو أكثر. على macOS/Linux شغّل:

   ```bash
   openssl rand -hex 32
   ```

5. في Vercel افتح `Project → Settings → Environment Variables` وأضف:
   - Name: `ASSESSMENT_SECRET`
   - Value: الناتج العشوائي من الأمر السابق
   - Environments: `Production`، و`Preview` عند الحاجة

   لا تضع القيمة في GitHub أو في ملفات الواجهة أو ترسلها في محادثة.
6. احفظ المتغير، ثم نفّذ Deployment جديدًا؛ متغيرات البيئة لا تُضاف إلى Deployments القديمة تلقائيًا.
7. افتح الموقع وابدأ الاختبار. إذا ظهرت رسالة تطلب `ASSESSMENT_SECRET`، راجع الخطوة 5 ثم أعد النشر.

## حماية إضافية موصى بها

- أبقِ مستودع GitHub خاصًا؛ جعل المستودع عامًا يكشف ملف `api/assessment.js`.
- من Vercel Firewall أنشئ Rate Limit على المسار `/api/assessment`، مثل 30 طلبًا لكل 60 ثانية لكل عنوان IP، وراقب الطلبات قبل تشديد الحد.
- لا يوجد أسلوب يمنع نسخ سؤال يراه شخص على الشاشة أو تصويره. التصميم هنا يمنع إرسال بنك الأسئلة الكامل ومفاتيح الإجابة والأوزان إلى المتصفح، ويجزّئ الأسئلة إلى دفعات، ويشترط جلسة موقعة قصيرة العمر. هذا يقلل الاستخراج الآلي ولا يمنعه بنسبة 100%.
- معرّفات الأسئلة التي تصل للمتصفح رموز غير كاشفة، بينما أبعاد القياس ومفاتيح الإجابة تظل في الخادم.

## الخصوصية

الإجابات تُحفظ في `localStorage` على جهاز المستخدم لاستكمال الاختبار. عند طلب النتيجة تُرسل إلى وظيفة Vercel لحسابها، ولا تنشئ هذه النسخة سجلًا دائمًا في قاعدة بيانات. منصة الاستضافة قد تحتفظ ببيانات تشغيلية وسجلات وفق إعداداتها وسياساتها. لا تجمع هذه النسخة بريدًا إلكترونيًا ولا تستخدم LLM.

## المدة والأسئلة

تظهر في صفحة البداية مدة واضحة: **20 دقيقة**، من دون عدّاد أو حد زمني. هذا تقدير تصميمي أولي؛ يجب معايرته بعد تجربة النسخة مع مجموعة مستخدمين مصريين ومراجعة زمن الإكمال الفعلي. يتكون الاختبار الحالي من 60 سؤالًا/موقفًا موزعة على الاهتمامات، السلوك اليومي، الاندماج، تحديات قصيرة، وطريقة العمل.

## الحدود العلمية

- الأسئلة عربية أصلية للموقع ومستوحاة من المراجع الظاهرة أسفلها، وليست بنودًا رسمية من تلك الأدوات إلا إذا ذُكر خلاف ذلك صراحة.
- أوزان المطابقة الحالية قواعد تشغيلية أولية خاصة بالموقع وليست معاملات معتمدة أو مقننة من O*NET أو من دراسة أكاديمية.
- تحديات التفكير لا تنتج درجة IQ أو تشخيصًا أو مقارنة معيارية.
- أفكار المشروعات فرضيات قابلة للاختبار وليست دراسة جدوى أو دليلًا على وجود طلب محلي.
- متطلبات الترخيص والأسعار والموردون والطلب في مصر يجب التحقق منها من مصادرها الحالية قبل اتخاذ قرار مالي أو مهني.
